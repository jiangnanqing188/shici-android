# 拾词 · Android 离线学习原型

独立 Kotlin 安卓 App，不是网站。用于验证“主界面开关 → 悬浮框选 → 本地 OCR → 本地释义 → 生词记录”的可行性。首个目标设备是 OPPO Pad 3，目标使用场景是海文考研英语题。2026-10-09 经用户授权，在 OPPO Pad 3 Pro（OPD2401）、Android 16 的平板完成首轮安装，并覆盖安装刷新修复/荧光笔原型后执行基础回归；不是完整海文兼容性验收。

## 当前开发接入：原始 kajweb 离线词库（任务开始 2026-10-10，跨日延续）

**开发候选为 `0.2.0` / versionCode `3`，不是已安装的 `0.1.1`。** 当前查词入口接入未逐条核对的五本原始词书，不应用已核验内容、候选修订或 ECDICT。旧演示记录按旧来源保留；原始资产标号 `20261010`、源清单日期 `20261009` 和固定来源版本不因跨日收尾而改写。

- 来源：`kajweb/dict · 有道来源备考词书`；固定版本 `3992bcb94c800a2fd38a9fd6ff95b2353e755363`。合并优先级为 `ky → cet4 → cet6 → tem4 → tem8`，仅合并完全相同的 `(pos, meaning)`，保留不同原义与词性，不重新撰写释义。
- 当前资产 **12,652 个唯一词头、26,572 条源行、25,289 对合并后原始词性/释义、0 个词形别名**。主线程独立从五个原 ZIP 对照确认上述集合和原义一致；这只是原数据保真证据，**不是语义正确性审核，也不是官方大纲覆盖验收**。
- 当前 12,652 词头全部符合 `[a-z]+(?:['-][a-z]+)*`，**不含 `a.`、`vs.`**。加载器的缩写、短语和重音词回归使用自编夹具，不代表当前资产实际覆盖这些内容。各词书原始数量为考研 4,533 / 四级 3,739 / 六级 2,078 / 专四 4,025 / 专八 12,197，集合重叠，不能相加当总词数。
- 压缩资产 SHA256：`de7fef8327f569d6bd4bd8ef24258e33839e42f2f5a3d3d9b24ea216b8539c0c`。运行时 `ShiciApplication.dictionary` 使用共享 lazy 结果，仅由现有 worker 读取并校验 manifest、压缩 SHA256、gzip CRC、Header、严格 UTF-8、四字段/转义、词头数量及重复；失败也缓存，缺失/损坏时明确提示，不生成释义、不增加记录或伪造词库数量。
- 手动输入和荧光笔查词共用 `RawKajwebDictionary`。NFC、小写、弯撇号和空白统一；保留原缩写句点的精确匹配，再处理句末句点。只查原始词头，不猜词形、不回退演示或 ECDICT，不把多个 OCR 词自动拼成一个词。首次加载在后台进行，首页/设置显示的是已通过格式与完整性校验的数量，不把“加载成功”写成“逐词核验”。
- 首页、设置、查询结果、生词详情、导出确认与 PDF 明示**原始未逐条核对、来源版本、不是官方大纲全覆盖词库**。PDF 按每条记录实际来源标注，混合旧演示记录不被统一冒称为新词库。
- 不迁移或清空个人数据库。只有新的成功查询才刷新该词的词性、释义、来源版本；笔记、掌握、旧事件保留。重复/已撤销事件重试不刷新词源、不重复计数；取消和失败事务全部回滚。

### 本地资产构建与许可边界

复用现有 `tools/dictionary/build_kajweb_app.py`，不增加构建框架、不联网。原 ZIP 在 `.tools/dictionaries/source-review-20261009/`；固定源清单为 `docs/dictionary/source-inventory-20261009.json`。下面的输出目录必须不存在；若已存在，改用另一个明确的新目录，构建器不会覆盖原目录。命令在项目根目录执行：

```bash
python3 tools/dictionary/build_kajweb_app.py \
  --manifest docs/dictionary/source-inventory-20261009.json \
  --source-dir .tools/dictionaries/source-review-20261009 \
  --output-dir .tools/dictionaries/kajweb-app-raw-local-1
mkdir -p app/src/main/assets/dictionary
cp .tools/dictionaries/kajweb-app-raw-local-1/assets/dictionary/kajweb.tsv.gz \
   app/src/main/assets/dictionary/kajweb.tsv.bin
cp .tools/dictionaries/kajweb-app-raw-local-1/assets/dictionary/kajweb-manifest.json \
   app/src/main/assets/dictionary/kajweb-manifest.json
```

构建器从固定原 ZIP 校验 SHA256 并生成资产，不读取核验/修订内容。复制前须确认目标确实是该候选；本轮主线程已从 `.tools/dictionaries/kajweb-app-raw-20261010/` 复制两文件并比对原资产。构建产物仍为 `kajweb.tsv.gz`；复制到运行资产时改名为 `kajweb.tsv.bin`，避免 AGP `mergeDebugAssets` 对 `.gz` 自动解压并移除后缀，导致运行时找不到压缩文件。仅改文件名，内容仍为原 GZIP 字节，原 SHA256 不变。运行资产 `kajweb.tsv.bin`（407,621 字节）及完整词义因**再分发许可待确认**只用于本地候选，按精确路径忽略，不纳入任务提交；小 `kajweb-manifest.json` 可提交。没有资产时必须先在本地生成并复制，只有源码和小 manifest 的检出不能直接获得可用词库。不得把本地试验当作公开发布许可。

- 导出确认前从数据库读取当前已提交结果，冻结搜索条件、词项与日期；确认后新增记录不混入该快照。取消/重建/迟到回调按请求标识隔离，不从界面旧缓存导出。没有改数据库版本或清库。
- 选择主交互改为半透明荧光笔：沿字形涂划，可多笔累积，抬笔换行不连接；“完成划选”才识别，“重画/取消”可放弃。旧矩形只留几何测试作为历史对照，不是默认入口。
- 原型参数：24dp可见笔宽，透明度96/255；每笔在截图内至少6dp，最终按中心线穿过内缩8%短边的词框判定。可见笔迹边缘擦过不一定命中，这是减少误选的原型取舍，不是已验证的最优规则。
- OCR在轨迹附近扩展64dp上下文，最终只选择轨迹命中的词；多词按OCR行位置和词位置恢复阅读顺序，保留大小写/标点/重复词/换行。选择一个词才查词，不批量自动入库。
- 译句未接入，无网络依赖或上传；四六级词书/复习/正式词典仍是待开发规划。快速单词操作目前多一次“完成”，响应体验仍需专项评价。
- 新增33项JVM测试，合计59项通过；本次四项Gradle构建成功，lint 0错误/10项建议。升级与设备回归证据以本轮开发进度、工作记录为准，不把本地测试当作设备验收。

## 捕获与隐私边界

- 该原型明确选择**全屏分享**，不是应用窗口捕获。首次开启先解释整屏权限，再走系统悬浮/通知/捕获授权。用户拒绝或取消不会留下“已开启”。Android 14+ 显式请求默认屏幕捕获。
- 临时截图只在内存保留；不录视频、不写截图文件、不上传。源码 manifest 用合并规则移除传递依赖的 `INTERNET` 与 `ACCESS_NETWORK_STATE`；最终 APK 的权限须核验合并 manifest，不能仅凭源码声明认定已离线。
- 点击入口移除本工具浮层，经下一显示帧回调后接受时间戳不早于该回调的新 ImageReader 图像。BUG-008 加入保守内容门禁：仅排除系统报告的可见系统栏/刘海区域，正文逐行全量扫描；只拒绝正文所有像素都透明或 RGB 各通道均≤3 的明显黑帧，任何可见非近黑内容（含稀疏文字）即放行，不使用平均亮度或粗网格采样。
- 黑帧在同一个请求内丢弃，继续等待后续新有效帧；保留原 4 秒截止时间，不固定 sleep、不延长等待、不复用旧截图。持续黑帧或无新有效帧会明确提示返回重试；不能据此断言页面受保护，也不绕过保护。排队中的有效帧交给主线程前仍核对 reader、查询 token、会话和截止时间，取消/旋转/停止后丢弃迟到帧并回收。
- 上述是 BUG-008 的黑帧过滤与竞态修复，不是已确认根因的消除：异常源可能仍产生黑帧，截图时间戳、设备系统边界和显示合成时序仍需真机核对。`12-study-reverse-ready.png` 的可见正文内部像素为 RGB(0,0,0)，但未保存当时原始捕获 Bitmap/insets，不能声称精确重现该设备帧或全部 ROM 无残影。新增 JVM 回归与 `FrameContentBitmapTest` 合成像素/ImageReader 测试；后者已在0.1.1固定测试包中运行通过；不等于入口无遮挡或长期稳定性通过。
- 每个会话只创建一个 VirtualDisplay，旋转/捕获尺寸变化替换 ImageReader 并调整显示尺寸；旧选区失效。原型拒绝超过 8192 单边或 16,777,216 总像素的捕获尺寸并停止会话，避免无界内存分配。
- OCR 使用独立裁剪位图，避免全区域裁剪返回原图时被提前回收。关闭卡片和停止服务使旧回调失效；服务关闭释放虚拟显示、捕获、浮层与识别器。停止期间显示“正在关闭”并阻止重开，待资源清理后才允许新授权；旧会话收尾按 generation 核对，不覆盖新授权状态。已有提交可从生词详情撤销，不删除整个历史词项。
- 临时静态画面**不暂停**题目计时、视频或底层应用行为。OCR 英文字形、截图方向/尺寸、通知/返回键及 OPPO 后台限制仍需实机确认。
- 不需要无障碍服务、相机、存储读写或账号权限。系统文件选择器用于 PDF 写入，App 关闭 Android 自动备份（未提供备份恢复功能）。

## Debug 性能日志（供后续真机阶段 B）

只在 debug 构建用 `ShiciPerf` 标签输出 logcat，不写文件、不联网、不做遥测面板；release 构建不输出本工具的性能日志。每次点击用随机匿名 `op` ID 串联，只有固定阶段/状态与毫秒耗时，不包含单词、OCR 文本、截图或用户笔记。

在已由用户授权连接的测试设备上，可采集 `adb logcat -s ShiciPerf:D`。工程不会自动执行设备连接或安装。

- `click`：点击入口；`selection_ready`：选词层第一次绘制，`click_to_selection_ms`。
- `selection_submit`：点击“完成划选”；`definition_visible`：释义内容第一次绘制，`submit_to_definition_ms`。不含画笔时间，不能和旧版“松手→释义”样本直接比较。
- `frame_rejected status=black`：同一请求首次丢弃明显黑帧（不记录像素/文字）；`frame_black_timeout`：遇到黑帧后未在期限内取得有效画面。
- `save`：提交状态；错误阶段包括 `frame_timeout`、`frame_conversion`、`ocr_empty`、`ocr`、`dictionary`、`session`；关闭/停止同样有状态日志。
- 所有计时使用 `SystemClock.elapsedRealtime()`；学习日期仍使用日历时间。第一次绘制是本轮交互就绪代理指标，不等于硬件光子级显示测量。
- `needs_confirmation` 标记多词/词形歧义；这些记录含人工确认等待，不应直接并入自动路径 P95。成功、未收录、取消、失败分别报告，不能只抽最快的样本。
- **0.1.1 本轮单次“点完成→释义”为340ms，未计算 P50/P95，不承诺性能达标。** 此前刷新/荧光笔回归日志为空，首轮旧版仅有少量“松手→释义”样本；不能跨版本混算。
