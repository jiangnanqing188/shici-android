- **R3 S2a-R2 异常来源失效：** `acquireLatestImage()` 正常返回 null（确实没有新图）仍视为中性，不取消查询；但它抛出异常，或当前 reader 返回与自身尺寸不符的 Image 时，会在捕获线程立即失效当前 guard 或已接受但未交付的请求（尚无 guard 时标记待挂载身份已变化），推进门禁后再通知主线程。入口/抬笔请求、offer→main 间隙、待挂载、guard、OCR/字典/保存准入均不能被静默当作“没有证据”；旧 reader 的迟到帧与代次已变化的会话不误杀新查询，已原子提交的记录不伪装回滚。
- **R3 S2e 非法布局拒绝：** 从 RGBA plane 读取/比较前验证真实布局：`pixelStride` 至少容纳 RGB 三通道，`rowStride` 至少容纳一整行图像像素（合法行尾 padding 仍接受），最后有效地址与 `body` 几何必须落在 buffer `limit` 内。像素步长 1、行步长 4 这类字节重叠不再被当作可证明同页；合法的 pixelStride 4/8、非零 body 偏移、ByteBuffer slice/direct/read-only、limit 以及末像素只含 RGB（无 alpha）的既有约定保持不变。该组是异常输入防御，不声称目标 Android 驱动常态产生非法 stride。

- **清洁帧来源与新鲜性：** 入口帧在移除「词」入口之后、挂载透明层之前请求；抬笔帧在移除透明层之后、显示任何结果/等待卡之前请求。两次都沿用现有 MediaProjection 会话与 ImageReader，只接受时间戳不早于对应 `Choreographer` 显示帧回调、在 2.5s（入口）/1.5s（抬笔）期限内、尺寸与当前捕获一致的图像；主体近黑帧继续丢弃并等待后续新帧，不复用旧截图、不固定 sleep。两张帧只在内存中保留有界页面身份后立即回收，不保留位图；抬笔帧与入口身份不一致时直接取消并提示重选，不 OCR、不查询。抬笔帧仅在内容一致后才裁剪笔迹附近区域做一次本地 OCR。
- **S1a 位置与颜色身份（R2）：** 不再使用分块或稀疏摘要。页面身份按屏幕坐标保存**每个像素的 RGB 5/6/5 量化颜色**：薄字、细线、同半区水平/垂直的一像素移动、同亮度不同颜色都可区分；相邻量化桶相差 ≤1（约 R/B 8 级、G 4 级）视为噪声，白 `0xFF` 与 `0xFE` 量化相同，因此低幅噪声仍接受。每个身份上限 8,388,608 像素 / 16 MiB（覆盖 3000×2120 平板页面并留余量），超限图像在读取前失败关闭并取消本次查询；一次取词最多同时驻留入口/抬笔两个身份，抬笔确认后立即丢弃入口身份，guard 只保留抬笔身份且最长 60 秒，保存、取消、重选、关闭、尺寸变化或服务停止都会释放。身份只驻留内存，不落盘、不上传、不渲染截图、不做全屏连续 OCR。
- **S1b/S2c 精确排除（R2）：** 页面比较按**像素**应用排除，只跳过本 App 当前结果卡/入口窗口实际覆盖的矩形；不再因排除框与 tile 相交就跳过整个 tile，不再向外固定扩 16dp，也不再累加历史卡框。卡片之外的可见选词邻域仍参与比较，卡片自身内容变化不会误伤同页查询；卡片外页面照常可滚动翻页，不增加全屏遮挡。

- 该原型明确选择**全屏分享**，不是应用窗口捕获。首次开启先解释整屏权限，再走系统悬浮/通知/捕获授权。用户拒绝或取消不会留下“已开启”。Android 14+ 显式请求默认屏幕捕获。
- 临时截图只在内存保留；不录视频、不写截图文件、不上传。源码 manifest 用合并规则移除传递依赖的 `INTERNET` 与 `ACCESS_NETWORK_STATE`；最终 APK 的权限须核验合并 manifest，不能仅凭源码声明认定已离线。
- 点击入口移除本工具浮层，经下一显示帧回调后接受时间戳不早于该回调的新 ImageReader 图像。入口帧在透明划词层挂载前取得；抬笔帧在划词层移除后、任何结果卡出现前取得。两次都要求同一捕获尺寸/方向、未过截止时间且未出现自己的入口/笔迹/卡片。BUG-008 加入保守内容门禁：仅排除系统报告的可见系统栏/刘海区域，正文逐行全量扫描；只拒绝正文所有像素都透明或 RGB 各通道均≤3 的明显黑帧，任何可见非近黑内容（含稀疏文字）即放行，不使用平均亮度或粗网格采样。
- 入口帧在内存中只保留有界逐像素颜色身份（Q1 R2：最多 8,388,608 像素 / 16 MiB per身份，超限失败关闭；抬笔身份在 guard 中最多 60 秒）后立即回收；抬笔帧先与入口身份按同一坐标逐像素比较，页面滚动/切换/尺寸或可见内容不一致即取消，不把旧页、黑帧或错方向图交给 OCR。自有点击入口/结果卡只按当前实际覆盖矩形逐像素排除，不扩大、不累加历史卡框。黑帧在同一个请求内丢弃，继续等待后续新有效帧；入口请求截止 2.5s、抬笔请求截止 1.5s，不固定 sleep、不延长等待、不复用旧截图。持续黑帧或无新有效帧会明确提示返回重试；不能据此断言页面受保护，也不绕过保护。排队中的有效帧交给主线程前仍核对 reader、查询 token、会话和截止时间；环境帧已到但无法读取时按“无法证明页面未变”取消旧查询。取消/旋转/停止后丢弃迟到帧并回收。
- 上述是 BUG-008 的黑帧过滤与竞态修复，不是已确认根因的消除：异常源可能仍产生黑帧，截图时间戳、设备系统边界和显示合成时序仍需真机核对。`12-study-reverse-ready.png` 的可见正文内部像素为 RGB(0,0,0)，但未保存当时原始捕获 Bitmap/insets，不能声称精确重现该设备帧或全部 ROM 无残影。新增 JVM 回归与 `FrameContentBitmapTest` 合成像素/ImageReader 测试；后者已在0.1.1固定测试包中运行通过；不等于入口无遮挡或长期稳定性通过。
- 每个会话只创建一个 VirtualDisplay，旋转/捕获尺寸变化替换 ImageReader 并调整显示尺寸；旧选区失效。原型拒绝超过 8192 单边或 16,777,216 总像素的捕获尺寸并停止会话，避免无界内存分配。
- OCR 使用独立裁剪位图，避免全区域裁剪返回原图时被提前回收。关闭卡片和停止服务使旧回调失效；服务关闭释放虚拟显示、捕获、浮层与识别器。停止期间显示“正在关闭”并阻止重开，待资源清理后才允许新授权；旧会话收尾按 generation 核对，不覆盖新授权状态。已有提交可从生词详情撤销，不删除整个历史词项。
- 取词时原页面保持显示并继续运行；全屏透明笔迹层只在这一次取词期间接收触摸，不注入或合成触摸到原应用。OCR 英文字形、屏幕方向/尺寸、通知/返回键及 OPPO 后台限制仍需实机确认。
- 不需要无障碍服务、相机、存储读写或账号权限。系统文件选择器用于 PDF 写入与本地备份/恢复；App 关闭 Android 系统自动备份，应用自身的本地学习数据备份/恢复为设置页显式操作（B3，见上节），不依赖系统自动备份。

## Debug 性能日志（供后续真机阶段 B）

只在 debug 构建用 `ShiciPerf` 标签输出 logcat，不写文件、不联网、不做遥测面板；release 构建不输出本工具的性能日志。每次点击用随机匿名 `op` ID 串联，只有固定阶段/状态与毫秒耗时，不包含单词、OCR 文本、截图或用户笔记。

在已由用户授权连接的测试设备上，可采集 `adb logcat -s ShiciPerf:D`。工程不会自动执行设备连接或安装。

- `click`：点击入口；`selection_ready`：原页面透明划词层已可划（干净入口帧已取得），`click_to_selection_ms`。
- `selection_submit`：单笔抬起提交；`definition_visible`：释义内容第一次绘制，`submit_to_definition_ms`。该区间包含抬笔帧取帧/一致性校验与 OCR，不包含画笔时间。
- `frame_rejected status=black`：同一请求首次丢弃明显黑帧（不记录像素/文字）；`frame_black_timeout`：遇到黑帧后未在期限内取得有效画面。
- `save`：提交状态；错误阶段包括 `frame_timeout`、`frame_conversion`、`ocr_empty`、`ocr`、`dictionary`、`session`；关闭/停止同样有状态日志。
- 所有计时使用 `SystemClock.elapsedRealtime()`；学习日期仍使用日历时间。第一次绘制是本轮交互就绪代理指标，不等于硬件光子级显示测量。
- `needs_confirmation` 标记多词/词形歧义；这些记录含人工确认等待，不应直接并入自动路径 P95。成功、未收录、取消、失败分别报告，不能只抽最快的样本。
- **0.1.1 本轮单次“点完成→释义”为340ms，未计算 P50/P95，不承诺性能达标。** 此前刷新/荧光笔回归日志为空，首轮旧版仅有少量“松手→释义”样本；不能跨版本混算。

## 代码入口

- `ui/MainActivity.kt`：五页界面（首页 / 生词本 / 统计 / 设置 / 背词）、权限流程、后台原始词库手动查词、来源/状态展示、PDF 文件选择、备份与恢复交互、恢复预览 v1/v2 文案。
- `ui/StudyScreen.kt`：背词复习界面（选词书、每日新词目标、显示答案与认识/模糊/忘记反馈、今日与到期待复习展示），只驱动 repository 的真实学习事务，不维护并行内存账。
- `capture/CaptureService.kt` / `LiveSelectionView.kt`：捕获会话、悬浮入口、原页面透明一笔划词、清洁入口/抬笔帧、本地 OCR 与结果卡；`SelectionView.kt` 保留旧静态截图选词实现供历史/测试参照，不再是产品入口。`core/LiveSelectionSession.kt`：非持久化的有界逐像素颜色身份、页面 guard 与单次取词状态。
- `core/RawKajwebDictionary.kt`：原始资产完整性校验、查词/归一化与未核对来源标注，当前运行时查词唯一入口；另有按 `entry_key` 取词条的只读方法供背词卡快照使用。
- `core/Study.kt`：背词数据模型（词书/反馈/设置/状态/卡/反馈记录/进度/视图）与固定间隔调度规则（`StudyRules`）。
- `core/StudyBooks.kt`：考研/六级归属索引的校验加载（manifest/数量/SHA-256/gzip/严格 UTF-8/逐条键唯一）；个人生词为运行时集合。
- `ShiciApplication.kt`：现有串行 worker、数据库与共享 lazy 词库/归属加载结果；不在 UI 线程加载。
- `core/Dictionary.kt`：词条携带来源/版本；保留 `DemoDictionary` 和旧词形测试，仅用于旧演示数据与回归，不参与当前运行时兜底。
- `data/LearningRepository.kt`：SQLite 事务、事件计数、撤销、个人数据、按 key 单事务删除（含该 key 的学习状态/反馈/待答卡）、背词学习事务（选书/目标、发牌、显示答案、提交反馈）、备份同一读事务读出原始所有表与 revision、恢复单事务先删后插做完整覆盖并含 schema v1→v2 迁移。
- `core/DeletionGate.kt`：进程内线程安全的删除代次；查询启动时捕获、贯穿识别/展示/保存/重试，只拦截被删词的旧回调，删除失败不推进代次；另有只在完整恢复成功后推进的全局恢复屏障。
- `core/LearningBackup.kt`：`.shicibackup` 的数据模型与版本化二进制编解码（格式 v2，v1 可读；严格 UTF-8、长度前缀、64MiB 上限、SHA-256 与结构校验，含设置/状态/反馈/待答卡）。
- `core/LearningBackupSession.kt`：备份导出与恢复流程的主线程会话门控（读→冻结→预览→安全备份→覆盖）与 request/阶段/一次性 token 隔离；恢复 apply 另持有跨线程可安全读取的一次性取消/准入凭据（`ApplyHandle`），在进入覆盖事务前对生命周期/旧会话失效线性化。
- `core/Geometry.kt` / `ExportLayout.kt`：可用 JVM 单测核对的几何与分页。
- `export/PdfExporter.kt`：系统 PDF 生成器。
- `tools/dictionary/build_study_books.py`：从固定只读来源 ZIP 生成考研/六级归属索引与清单（构建产物流水线，复用只读 `audit_exam_sources`；不改动也不重写原字典生成工具）。

工程是当前唯一运行源码；`docs/design/ui-concept.png` 是设计参考，不是运行时整页图片。
