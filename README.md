- **本地二进制格式 `.shicibackup`（无新增依赖，纯 Kotlin/JDK）：**

  ```
  文件 = 主体 ‖ SHA-256(主体)            # 末尾固定 32 字节校验和，覆盖前面全部字节
  主体（大端序）：
    magic             8 字节 ASCII "SHICIBKP"
    format_version    int32 = 2
    app_identity      长度前缀 UTF-8 = "com.shici.app"
    app_version_name  长度前缀 UTF-8        # 写出时的应用版本名
    app_version_code  int32
    db_schema_version int32 = 2
    created_at        int64                 # UTC 毫秒
    word_count        int32
    event_count       int32
    word_count  × 词条：entry_key, headword, pos, meaning, source, version（均长度前缀 UTF-8）
                        mastered（1 字节 0/1）, note（长度前缀 UTF-8）
    event_count × 事件：id, entry_key, raw_text, final_form（均长度前缀 UTF-8）
                        time（int64）, revoked（1 字节 0/1）
    -- 以下为格式 v2 新增（背词复习）--
    selected_book     长度前缀 UTF-8 = "ky" / "cet6" / "personal"
    daily_new_goal    int32                 # 1–200
    state_count       int32
    state_count × 学习状态：entry_key, book（均长度前缀 UTF-8）
                        stage（int32 0–4）, due_at, introduced_at, last_review_at（均 int64）
    review_count      int32
    review_count × 反馈：token, entry_key, feedback, day_key, zone_id（均长度前缀 UTF-8）
                        stage_before（int32 −1–4）, stage_after（int32 0–4）, due_after（int64）
                        reviewed_at（int64）, new_word（1 字节 0/1）
    has_pending_card  1 字节 0/1            # 为 1 时其后为 1 张待答卡
                      待答卡：token, entry_key, book, headword, pos, meaning, source, version, day_key（均长度前缀 UTF-8）
                        stage_before（int32 −1–4）, created_at（int64）, new_word 与 answer_revealed（各 1 字节 0/1）
  长度前缀 UTF-8 = int32 字节长度 + 严格 UTF-8 字节   # 不使用 DataOutput.writeUTF 的 64KiB 限制
  ```

  单文件上限 **64MiB**，写出与读取前后都有边界检查；读取时声明长度超限或越界即拒绝，不按声明长度无界分配。读取在写库前完整校验：文件大小、SHA-256 校验和、magic、格式版本（**高于当前 v2 明确拒绝，不猜成当前格式**；**v1 文件仍可读**）、应用标识、数据库 schema（v2 文件要求 schema=2，v1 文件要求 schema=1）、每个长度前缀/严格 UTF-8/布尔字节、重复 `entry_key`、重复事件 `id`、重复反馈 `token`、无对应词条的事件（孤儿）、学习状态/反馈/待答卡对 `words` 的引用、阶段范围、`new_word` 与 `stage_before` 一致性、待答卡 token 不得与反馈 token 冲突、以及声明内容之后的多余字节。已有合法空字符串、长笔记与 Unicode **不做无依据截断或“修正”**。文件为**本地明文个人数据，不加密、不防恶意篡改**（仅 SHA-256 完整性校验），界面明确提示妥善保存。
- **旧格式（v1 / schema1）兼容：** v1 文件仍可读取，预览会**明确标注“不含背词进度”**；用 v1 文件完整覆盖恢复后，`words`/`events` 原样还原，**学习状态/反馈/待答卡为空、所选词书与每日目标恢复默认**（等同 v1→v2 迁移后的空学习库），不再额外提示可用背词进度。恢复前安全备份始终按**当前格式 v2** 写出，因此安全备份可读回校验且不会丢失学习进度。
- **恢复安全契约（完整覆盖，同一 worker）：** 选定的导入文件先被**完整读取、验证并冻结**，预览其创建日期与词/事件数量，再经**二次明确确认**；解析/预览/确认都不算已恢复。确认后由既有单线程 worker 在同一流程中：读取当前 `words`/`events` 原始两表与 `changes.version` → 要求用户把这份**恢复前快照**另存到一个所选文档 → **写入、关闭并读回逐字节比对**成功 → 再检查当前 `changes.version` 仍等于快照 revision → 才执行覆盖替换。安全备份位置**不得与导入源 URI 相同**。覆盖在**同一事务**内先删 `events`/`words` 再插 `words`/`events`，任一步失败整体回滚；只有 `endTransaction` 成功后才发布一次变化并报告成功。revision 漂移、取消、权限/IO/校验失败一律**不写学习库、不发布、不显示成功**，也**不自动删除任何用户文件**；空备份可合法清空学习数据，但同样需明确预览与确认并先成功保存当前数据。
- **恢复成功后的全局失效：** `DeletionGate` 最小扩展一个**全局恢复屏障**，只在恢复成功提交后推进；它使恢复前捕获的**全部**手动/OCR 在途保存、重试、纠错、撤销与详情凭据失效（含备份里未出现的词），恢复后新主动查询按新凭据正常工作。普通查询与按词删除不推进该屏障，B2 的按词删除隔离（只失效被删词、失败不失效）与 R5 的原快照来源判别保持。
- **UI 与请求隔离：** 备份/恢复仅通过系统文档选择器创建/读取文件，不申请存储权限、不联网、不包含完整词库/PDF/截图/会话/应用暂态，也不改写或删除既有原词库与已导出文件。文件请求与 PDF 导出共用**同一个** request-code 分配器（`LearningExportSession.allocateRequestCode`），互不碰撞；回调用精确 request/阶段/一次性 token 隔离，旧/重复/取消/晚到回调不应用到新会话。Activity 重建或进程丢失且冻结状态不在时，只提示重新开始，**不从 URI 自动恢复、不自动删文件**（已进入事务的提交原子完成）。备份/恢复工作期间入口互斥并显示真实状态，关闭悬浮查词也可使用。
- **R2 生命周期与旧会话隔离修正（0.4.1 / 11）：** 正在 apply 的恢复操作在 `LearningRestoreSession` 中绑定一个**跨线程可安全读取的一次性取消/准入凭据**（`ApplyHandle`，`@Volatile` + 短 `synchronized`）。`onDestroy`（经 `restoreSession.clear`）、会话 `clear` 或新会话会让旧操作失效，worker 在**开始时**、**安全备份写入/关闭/读回校验完成后**、以及**最终进入覆盖事务前**都以该凭据复核，而不是只靠主线程 `isDestroyed` 或清空冻结字段判断。在进入覆盖事务前已失效的 apply **不写学习库、不推进全局恢复屏障、不显示成功**；最终 `admit()` 与失效在同一把短锁上线性化，消除“检查有效→任意间隙内 clear→仍 beginTransaction”的无保护 TOCTOU，且**不在安全备份 IO 全程持锁**、不会阻塞 UI 销毁。一旦 apply 已明确准入事务，随后到达的销毁**允许该事务原子提交**（不伪称已取消、不半写、不要求中途强制回滚）。完成回调只结算本操作（`finish` 受请求/阶段保护），旧回调不能结束新会话或清掉新 busy；正常完整恢复、单次消费与重复结果拒绝、revision 防漂移、安全备份逐字读回校验均保持不变。

## 捕获与隐私边界

- 该原型明确选择**全屏分享**，不是应用窗口捕获。首次开启先解释整屏权限，再走系统悬浮/通知/捕获授权。用户拒绝或取消不会留下“已开启”。Android 14+ 显式请求默认屏幕捕获。
- 临时截图只在内存保留；不录视频、不写截图文件、不上传。源码 manifest 用合并规则移除传递依赖的 `INTERNET` 与 `ACCESS_NETWORK_STATE`；最终 APK 的权限须核验合并 manifest，不能仅凭源码声明认定已离线。
- 点击入口移除本工具浮层，经下一显示帧回调后接受时间戳不早于该回调的新 ImageReader 图像。入口帧在透明划词层挂载前取得；抬笔帧在划词层移除后、任何结果卡出现前取得。两次都要求同一捕获尺寸/方向、未过截止时间且未出现自己的入口/笔迹/卡片。BUG-008 加入保守内容门禁：仅排除系统报告的可见系统栏/刘海区域，正文逐行全量扫描；只拒绝正文所有像素都透明或 RGB 各通道均≤3 的明显黑帧，任何可见非近黑内容（含稀疏文字）即放行，不使用平均亮度或粗网格采样。
- 入口帧在内存中只保留有界逐像素颜色身份（Q1 R2：最多 8,388,608 像素 / 16 MiB per身份，超限失败关闭；抬笔身份在 guard 中最多 60 秒）后立即回收；抬笔帧先与入口身份按同一坐标逐像素比较，页面滚动/切换/尺寸或可见内容不一致即取消，不把旧页、黑帧或错方向图交给 OCR。自有点击入口/结果卡只按当前实际覆盖矩形逐像素排除，不扩大、不累加历史卡框。黑帧在同一个请求内丢弃，继续等待后续新有效帧；入口请求截止 2.5s、抬笔请求截止 1.5s，不固定 sleep、不延长等待、不复用旧截图。持续黑帧或无新有效帧会明确提示返回重试；不能据此断言页面受保护，也不绕过保护。排队中的有效帧交给主线程前仍核对 reader、查询 token、会话和截止时间；环境帧已到但无法读取时按“无法证明页面未变”取消旧查询。取消/旋转/停止后丢弃迟到帧并回收。
- 上述是 BUG-008 的黑帧过滤与竞态修复，不是已确认根因的消除：异常源可能仍产生黑帧，截图时间戳、设备系统边界和显示合成时序仍需真机核对。`12-study-reverse-ready.png` 的可见正文内部像素为 RGB(0,0,0)，但未保存当时原始捕获 Bitmap/insets，不能声称精确重现该设备帧或全部 ROM 无残影。新增 JVM 回归与 `FrameContentBitmapTest` 合成像素/ImageReader 测试；后者已在0.1.1固定测试包中运行通过；不等于入口无遮挡或长期稳定性通过。
- 每个会话只创建一个 VirtualDisplay，旋转/捕获尺寸变化替换 ImageReader 并调整显示尺寸；旧选区失效。原型拒绝超过 8192 单边或 16,777,216 总像素的捕获尺寸并停止会话，避免无界内存分配。
- OCR 使用独立裁剪位图，避免全区域裁剪返回原图时被提前回收。关闭卡片和停止服务使旧回调失效；服务关闭释放虚拟显示、捕获、浮层与识别器。停止期间显示“正在关闭”并阻止重开，待资源清理后才允许新授权；旧会话收尾按 generation 核对，不覆盖新授权状态。已有提交可从生词详情撤销，不删除整个历史词项。
- 取词时原页面保持显示并继续运行；全屏透明笔迹层只在这一次取词期间接收触摸，不注入或合成触摸到原应用。OCR 英文字形、屏幕方向/尺寸、通知/返回键及 OPPO 后台限制仍需实机确认。
- 不需要无障碍服务、相机、存储读写或账号权限。系统文件选择器用于 PDF 写入与本地备份/恢复；App 关闭 Android 系统自动备份，应用自身的本地学习数据备份/恢复为设置页显式操作（B3，见上节），不依赖系统自动备份。

## 代码入口

- `ui/MainActivity.kt`：五页界面（首页 / 生词本 / 统计 / 设置 / 背词）、权限流程、后台原始词库手动查词、来源/状态展示、PDF 文件选择、备份与恢复交互、恢复预览 v1/v2 文案。
- `ui/StudyScreen.kt`：背词复习界面（选词书、每日新词目标、显示答案与认识/模糊/忘记反馈、今日与到期待复习展示），只驱动 repository 的真实学习事务，不维护并行内存账。
- `capture/CaptureService.kt` / `LiveSelectionView.kt`：捕获会话、悬浮入口、原页面透明一笔划词、清洁入口/抬笔帧、本地 OCR 与结果卡；`SelectionView.kt` 保留旧静态截图选词实现供历史/测试参照，不再是产品入口。`core/LiveSelectionSession.kt`：非持久化的有界逐像素颜色身份、页面 guard 与单次取词状态。
- `core/RawKajwebDictionary.kt`：原始资产完整性校验、查词/归一化与未核对来源标注，当前运行时查词唯一入口；另有按 `entry_key` 取词条的只读方法供背词卡快照使用。
- `core/Study.kt`：背词数据模型（词书/反馈/设置/状态/卡/反馈记录/进度/视图）与固定间隔调度规则（`StudyRules`）。
- `core/StudyBooks.kt`：考研/六级归属索引的校验加载（manifest/数量/SHA-256/gzip/严格 UTF-8/逐条键唯一）；个人生词为运行时集合。
- `ShiciApplication.kt`：现有串行 worker、数据库与共享 lazy 词库/归属加载结果；不在 UI 线程加载。
- `core/Dictionary.kt`：词条携带来源/版本；保留 `DemoDictionary` 和旧词形测试，仅用于旧演示数据与回归，不参与当前运行时兜底。
- `data/LearningRepository.kt`：SQLite 事务、事件计数、撤销、个人数据、按 key 单事务删除（含该 key 的学习状态/反馈/待答卡）、背词学习事务（选书/目标、发牌、显示答案、提交反馈）、备份同一读事务读出原始所有表与 revision、恢复单事务先删后插做完整覆盖并含 schema v1→v2 迁移。
- `core/DeletionGate.kt`：进程内线程安全的删除代次；查询启动时捕获、贯穿识别/展示/保存/重试，只拦截被删词的旧回调，删除失败不推进代次；另有只在完整恢复成功后推进的全局恢复屏障。
- `core/LearningBackup.kt`：`.shicibackup` 的数据模型与版本化二进制编解码（格式 v2，v1 可读；严格 UTF-8、长度前缀、64MiB 上限、SHA-256 与结构校验，含设置/状态/反馈/待答卡）。
- `core/LearningBackupSession.kt`：备份导出与恢复流程的主线程会话门控（读→冻结→预览→安全备份→覆盖）与 request/阶段/一次性 token 隔离；恢复 apply 另持有跨线程可安全读取的一次性取消/准入凭据（`ApplyHandle`），在进入覆盖事务前对生命周期/旧会话失效线性化。
- `core/Geometry.kt` / `ExportLayout.kt`：可用 JVM 单测核对的几何与分页。
- `export/PdfExporter.kt`：系统 PDF 生成器。
- `tools/dictionary/build_study_books.py`：从固定只读来源 ZIP 生成考研/六级归属索引与清单（构建产物流水线，复用只读 `audit_exam_sources`；不改动也不重写原字典生成工具）。

工程是当前唯一运行源码；`docs/design/ui-concept.png` 是设计参考，不是运行时整页图片。
