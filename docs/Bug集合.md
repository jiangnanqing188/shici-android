## 一、还没修好／尚未关闭的 Bug

### BUG-001：悬浮查词后主界面未及时刷新，PDF 可能导出旧数据

| 项目 | 内容 |
|---|---|
| 状态 | **代码已修，端到端真机回归待完成（暂不关闭）** |
| 优先级 | **优先完成真机验收**：影响数据展示与导出可信度；旧包复现没有发现记录丢失，新版升级数据保留通过 |
| 发现日期 | 2026-10-09 |
| 影响范围 | 首页查询计数、生词本词项/查询次数、基于界面缓存生成的 PDF |
| 涉及源码 | `app/src/main/java/com/shici/app/ui/MainActivity.kt`、`app/src/main/java/com/shici/app/data/LearningRepository.kt`、`app/src/main/java/com/shici/app/core/LearningChanges.kt`、`app/src/main/java/com/shici/app/core/LearningExport.kt`；悬浮调用入口为 `app/src/main/java/com/shici/app/capture/CaptureService.kt` |

**旧包现象与复现步骤（`ae3affc`，不是新版复现）**

1. 打开拾词，保持主界面在前台。
2. 开启悬浮查词，在自己的测试画面框选 `evidence`，等待显示保存成功。
3. 返回做题并关闭悬浮查词；不点“刷新统计”，也不重启应用。
4. 查看首页，切换生词本，直接导出 PDF。
5. 实测数据库中 `evidence` 已有 **3 次有效查询**，但旧界面和导出的 PDF 仍显示 **2 次**；首页今日查询仍为3，实际有效查询总数为4。

**旧包已确认依据**

- 真机工作记录：[20261009-1-安卓安装包真机测试工作记录](../工作记录/20261009-1-安卓安装包真机测试工作记录.md)。
- 本地证据目录：`artifacts/device-tests/20261009/`（忽略目录，不进入 Git）。
- `learning-after-ocr.db`：evidence3次、study1次有效记录；`33-capture-stopped.xml`、`35-pdf-saved.xml` 和 `shici-usb-test-20261009.pdf` 仍使用旧计数。
- 重新读取后，`36-portrait-vocabulary.xml`、`38-final-stats.xml` 与数据库一致。

**历史原因定位（旧代码）**

旧代码中，`MainActivity` 缓存 `words`/`stats`，在 `onStart()` 或显式 `refresh()` 时重新读库；导航只执行 `render()`。`CaptureService` 写库后没有让仍在前台的主界面缓存失效，PDF 又使用这份缓存冻结内容。这是旧包的源码定位与真机复现依据，不是现行代码仍未处理的结论。

**已经改好的代码（`c28f282`）**

- `LearningRepository` 在事务成功结束后发布学习数据变更；回滚和无变化重试不发布变更。
- `MainActivity` 前台订阅变更，重新读取词项与统计；刷新请求有版本隔离，详情局部更新保留未保存的笔记/掌握输入。
- 导出确认前从数据库读取已提交数据，再冻结搜索条件、词项与日期；不再直接使用主界面旧缓存。取消、重建和迟到回调按导出请求标识隔离。
- 已有 59 项 JVM、17 项设备测试通过，保留数据升级通过；没有改变数据库版本、清库或卸载。

**现在还需要完成什么**

1. **最高优先：**主界面保持前台，悬浮查词新增后，不手动刷新或重启，核对首页、生词本、统计和数据库立即一致。
2. **同轮验证：**悬浮撤销、纠错后计数一致；笔记和掌握状态仍保留，重复回调不多记。
3. **导出回归：**立即导出包含最新提交；确认显示后再新增查询，不混入原冻结快照；确认取消、保存位置取消、旋转重建和重复点击不串快照。
4. **收尾验证：**停止后无捕获、服务或浮层残留，保留新证据后再决定关闭 BUG-001；失败则沿用此编号补充新版复现，不凭旧原因继续改代码。

不通过清空数据库、删除生词、关闭自动保存或取消冻结快照绕过问题。

**旧包临时办法**

旧包中可先进入统计页点“刷新统计”，再返回生词本导出；重启应用也会重新读取。新版已经加入自动刷新，手动刷新只作为发现异常时的临时兜底，不能拿它代替新版验收。

**修复验收标准**

- 主界面保持前台时，悬浮新增后不需要手动刷新，首页/生词本/统计即与数据库一致。
- 悬浮撤销、纠错后同样一致；重复回调不新增次数，已有笔记和掌握状态不丢失。
- 立即导出的 PDF 包含最新词项、正确查询次数和已保存笔记。
- 导出确认后发生新的查询，仍导出确认时的冻结快照，不混入后续内容。
- 现有 JVM 与 SQLite 设备测试回归通过，并在本次平板重跑上述链路，保存新证据后才能转入“已修复”。

### BUG-002：API 27 样式放在 API 26 公共资源，导致 lint 错误

- **状态：已修复，本地构建/lint 已验证。**
- 历史现象：原型支持最低 API26，但 API27 样式放在公共资源，首轮 lint 报错。
- 已做修复：把版本专属样式放入 `app/src/main/res/values-v27/styles.xml`，保留公共基础样式。
- 验证：最终 Gradle 构建与 lint 通过；历史 UI 基线 `ae3affc` lint 为 0 错误、5 项建议；当前 `c28f282` 为 0 错误、10 项建议，不是新增阻断错误。

### BUG-003：匿名原生 TextView 与 lint 的 AppCompat 规则冲突

- **状态：已修复，本地构建/lint 已验证。**
