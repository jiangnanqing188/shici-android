## 一、未修复的 Bug

### BUG-001：悬浮查词后主界面未及时刷新，PDF 可能导出旧数据

| 项目 | 内容 |
|---|---|
| 状态 | **代码已修，端到端真机回归待完成（暂不关闭）** |
| 优先级 | **优先修复**：影响数据展示与导出可信度，但本次没有发现数据库记录丢失 |
| 发现日期 | 2026-10-09 |
| 影响范围 | 首页查询计数、生词本词项/查询次数、基于界面缓存生成的 PDF |
| 涉及源码 | `app/src/main/java/com/shici/app/ui/MainActivity.kt`；`app/src/main/java/com/shici/app/capture/CaptureService.kt` |

**现象与复现步骤**

1. 打开拾词，保持主界面在前台。
2. 开启悬浮查词，在自己的测试画面框选 `evidence`，等待显示保存成功。
3. 返回做题并关闭悬浮查词；不点“刷新统计”，也不重启应用。
4. 查看首页，切换生词本，直接导出 PDF。
5. 实测数据库中 `evidence` 已有 **3 次有效查询**，但旧界面和导出的 PDF 仍显示 **2 次**；首页今日查询仍为3，实际有效查询总数为4。

**已确认依据**

- 真机工作记录：[20261009-1-安卓安装包真机测试工作记录](../工作记录/20261009-1-安卓安装包真机测试工作记录.md)。
- 本地证据目录：`artifacts/device-tests/20261009/`（忽略目录，不进入 Git）。
- `learning-after-ocr.db`：evidence3次、study1次有效记录；`33-capture-stopped.xml`、`35-pdf-saved.xml` 和 `shici-usb-test-20261009.pdf` 仍使用旧计数。
- 重新读取后，`36-portrait-vocabulary.xml`、`38-final-stats.xml` 与数据库一致。

**原因定位**

静态代码检查显示：`MainActivity` 缓存 `words`/`stats`，在 `onStart()` 或显式 `refresh()` 时重新读库；导航只执行 `render()`。`CaptureService` 写库后没有让仍在前台的主界面缓存失效，PDF 又使用这份缓存冻结内容。此处是源码定位依据，数据陈旧现象本身已在真机复现。

**现在需要修什么**

- 悬浮查词成功保存后，使首页、生词本和统计重新读取已提交的记录。
- 悬浮撤销、纠错后也要核对并保持一致；这两种操作在同一机制下是否全部受影响，需要补充回归，不冒称已经逐项复现。
- 开始导出确认时使用当前已提交数据，并继续保持“确认时冻结、选择位置期间不变”的原有规则。
- 不通过清空数据库、删除生词、关闭自动保存或取消冻结快照来绕过问题。

**临时办法**

悬浮查词后，先进入统计页点“刷新统计”，再返回生词本导出；重启应用也会重新读取。它只是临时办法，不能算 Bug 已修复。

**修复验收标准**

- 主界面保持前台时，悬浮新增后不需要手动刷新，首页/生词本/统计即与数据库一致。
- 悬浮撤销、纠错后同样一致；重复回调不新增次数，已有笔记和掌握状态不丢失。
- 立即导出的 PDF 包含最新词项、正确查询次数和已保存笔记。
- 导出确认后发生新的查询，仍导出确认时的冻结快照，不混入后续内容。
- 现有 JVM 与 SQLite 设备测试回归通过，并在本次平板重跑上述链路，保存新证据后才能转入“已修复”。

## 二、已经修复的 Bug

以下6项来自历史开发工作记录。修复包含在功能基线提交 `7167c5b` 中；该提交是包含修复的交付基线，不是每一项独立的修复提交。后续 UI 基线 `ae3affc` 重新构建通过。

### BUG-002：API 27 样式放在 API 26 公共资源，导致 lint 错误

- **状态：已修复，本地构建/lint 已验证。**
- 历史现象：原型支持最低 API26，但 API27 样式放在公共资源，首轮 lint 报错。
- 已做修复：把版本专属样式放入 `app/src/main/res/values-v27/styles.xml`，保留公共基础样式。
- 验证：最终 Gradle 构建与 lint 通过；当前 UI 基线 lint 为0错误、5项建议警告。
- 未验证：Android26/27实体设备的样式显示；本次Android16不覆盖该兼容分支。

### BUG-003：匿名原生 TextView 与 lint 的 AppCompat 规则冲突

- **状态：已修复，本地构建/lint 已验证。**
- 历史现象：第二轮 lint 对匿名原生 TextView 报错，阻止整体验证通过。
- 已做修复：调整悬浮入口实现为独立的原生 `BubbleView`，保留点击和拖动路径。
- 涉及文件：`app/src/main/java/com/shici/app/capture/BubbleView.kt`。
- 验证：最终 lint 无该错误；2026-10-09 真机浮钮显示、点击进入框选通过。拖动行为没有在本轮专项验收。

### BUG-004：浮层创建失败后，状态仍可能显示“已开启”

- **状态：已修复，代码审查及本地构建已验证；失败分支真机待验证。**
- 历史问题：创建浮层失败时，后续状态更新可能覆盖错误，界面显示与实际浮层不一致。
- 已做修复：只有 `showBubble()` 成功才进入 ACTIVE；浮层创建异常走失败停止路径。
- 涉及文件：`app/src/main/java/com/shici/app/capture/CaptureService.kt`。
- 验证：历史审查修正记录与构建通过；本次正常开启、取消和停止状态通过。
- 未验证：没有在平板上注入窗口创建异常，正常流程通过不等于异常分支已真机通过。

### BUG-005：过期异步回调可能覆盖新的查询界面

- **状态：已修复，查询标识隔离的 JVM 测试及本地构建已验证。**
- 历史问题：旧识别/查询结果迟到时，可能作用到已关闭或更新后的界面。
- 已做修复：使用 `QueryGate` 的查询版本标识；新查询、关闭、取消和停止使旧标识失效；异步结果须核对当前标识和会话。
- 涉及文件：`app/src/main/java/com/shici/app/core/QueryGate.kt`、`app/src/main/java/com/shici/app/capture/CaptureService.kt`、`app/src/main/java/com/shici/app/ui/MainActivity.kt`。
- 验证：`QueryGateTest.nextSelectionDismissAndStopInvalidateOldCallbacks` 已在历史26项JVM回归中通过；本次正常取消/撤销/关闭通过。
- 未验证：未在真机人工延迟回调并执行高频并发竞态测试。

### BUG-006：OCR 位图可能在识别结束前被释放

- **状态：已修复，代码审查、本地构建及正常 OCR 真机路径已验证。**
- 历史问题：裁剪结果可能复用原位图，关闭选词层时回收原图，导致 OCR 输入提前失效。
- 已做修复：为 OCR 保留独立裁剪位图，在识别完成回调回收，避免跟选词截图共用同一生命周期。
- 涉及文件：`app/src/main/java/com/shici/app/capture/CaptureService.kt`。
- 验证：历史审查修正与构建通过；本次 `study`、`evidence` 两个 OCR 成功样本。
- 未验证：全区域裁剪、识别中关闭/旋转及长时间内存压力未专项覆盖。

### BUG-007：快速关闭再开启时，旧会话收尾可能覆盖新状态

- **状态：已修复，代码审查及本地构建已验证；快速切换压力测试待验证。**
- 历史问题：旧捕获会话异步释放资源时，可能干扰下一次授权/新会话状态。
- 已做修复：STOPPING期间阻止重开，使用会话generation核对启动和收尾；旧会话清理不能覆盖新授权状态。
- 涉及文件：`app/src/main/java/com/shici/app/capture/CaptureStatus.kt`、`app/src/main/java/com/shici/app/capture/CaptureService.kt`、`app/src/main/java/com/shici/app/ui/MainActivity.kt`。
- 验证：历史审查修正与构建通过；本次普通关闭后无捕获、服务或浮层残留。
- 未验证：未在平板执行快速反复开关压力测试；不能用普通停止通过代替竞态验证。
