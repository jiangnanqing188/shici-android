## 1. 结论与产品定位

### 1.1 结论

建议做一个面向个人学习的安卓原生工具，先针对 OPPO Pad 3 和海文考研真实题目页面验证。

**产品形态已明确：一个有完整主界面的独立 App，悬浮窗只是用户可选择开启或关闭的跨应用查词入口，不是软件的全部界面。** 关闭悬浮窗后，主界面的生词本、统计和导出打印仍可使用。

推荐的主路径是：

**打开 App 主界面并开启悬浮查词 → 点击悬浮按钮 → 获取当前画面 → 在临时画面上框选单词 → 本地识别 → 本地词典查询 → 显示释义 → 保存查询记录 → 返回做题。**

完整生词本再增加日期筛选、重复查询统计、个人笔记和 A4 PDF 导出。

项目分成两条同时需要成立的验收线：

- **体验线：** 相比目前的截图翻译和手动输入，实际查词步骤更少、等待更短。
- **内容线：** 识别出的英文正确，词形处理可核对，词典来源明确且释义可信。

不能用“查得快”掩盖解释错误，也不能以“词典权威”为由接受每次等待数秒。第一版不依赖在线大模型生成释义，不用云端 OCR 作为默认路径。

### 1.2 要解决的问题

用户英语基础较弱，在平板看完网课后，需要在海文考研软件里做题。遇到大量生词时，截图、切换软件、裁剪或拼写单词会打断阅读。

本工具不是完整翻译软件，也不是网课软件，而是一个“随手查词并积累个人生词”的辅助工具。

### 1.3 何时才算有价值

不是弹出了一张释义卡片就算成功。实际应做到：

1. 查一个词时不需要退出做题页面去输入。
2. 常规使用中等待足够短，不频繁重新授权。
3. 识别失败不会悄悄变成错误生词。
4. 重复遇到的词能够累积次数，而不是产生大量重复条目。
5. 打印材料清楚、可核对，能真正拿来背诵。

## 2. 已确认事实、假设和待验证事项

### 2.1 已确认事实（来自用户）

| 项目 | 已确认内容 |
|---|---|
| 学习设备 | 安卓平板 OPPO Pad 3 |
| 目标软件 | 海文考研 |
| 使用场景 | 网课后在软件内做英语题 |
| 页面截图 | 用户已实际截图，题目文字能正常显示 |
| 首要要求 | 响应快，词汇数据准确 |
| 软件形态 | 有独立主界面的 App；用户可以选择开启或关闭悬浮窗 |
| 期望交互 | 主界面管理学习数据；开启悬浮入口后，用手指或笔选取想查的单词 |
| 记录需求 | 本地保存释义，统计，最终可以打印 |
| 当前请求 | 先编写详细方案，供审阅；并非授权开始开发或安装 |

### 2.2 本方案采用的假设（尚待确认）

- 第一阶段仅个人使用，不上架、不向其他人分发词库。
- 用户愿意在开始学习时完成系统必要的屏幕捕获授权。
- 第一阶段可以先接受“框选单词”，之后再优化到下划线取词。
- 首先验证全屏做题；分屏、小窗、复杂窗口缩放暂不纳入首轮验收。
- 基本查词不联网；暂不提供发音、整句翻译、自动语境判义。
- 正式词库的预算、版本和授权方案没有确定，不默认用户接受付费。

### 2.3 待验证事项

- 平板实际 Android / ColorOS 版本、可用存储空间。
- 海文考研 App 的具体版本、题目页面类型、字号和横竖屏使用习惯。
- 海文是否允许第三方悬浮窗在题目页显示。
- MediaProjection 捕获题目页是否正常；“手动截图成功”不能代替此项验证。
- 本地识别模型在该设备、断网环境和长时间学习后的速度与识别质量。
- 若设备没有可用的 Google Play 服务，选择的打包模型是否能正常初始化和运行。
- 是否使用触控笔及其型号；手指操作作为基本能力，专用笔按键不作为前提。
- 单应用捕获与全屏捕获中，哪种更适合实际交互和隐私要求。

**这些是后续检查清单，不需要在审阅方案前一次性全部回答。**

## 3. 功能范围与优先级

### 3.1 P0：技术验证原型

| 功能 | 首轮要求 |
|---|---|
| App 主界面 | 原型即提供基本首页，不只提供一个悬浮球 |
| 悬浮查词开关 | 主界面明确控制开启和关闭，同步实际捕获会话状态 |
| 悬浮按钮 | 可显示、拖动、收起；平时不挡做题操作 |
| 当前画面获取 | 只使用新鲜、无本工具遮挡的画面 |
| 框选取词 | 手指或触控笔拖出矩形，能看到选中范围 |
| 本地英文识别 | 不上传截图，能够显示识别出的英文 |
| 本地词典查询 | 返回来源标明的基本释义；缺词明确提示 |
| 返回做题 | 可取消和关闭，不能误触题目答案 |
| 性能测量 | 记录各阶段耗时、成功与失败类别 |

原型可使用经检查的测试词库或自编少量演示词条。若正式词库仍未选定，必须在界面与报告中标明“技术演示数据”，不能声称内容已达到长期背诵标准。

### 3.2 P1：个人日用版

- 完整主界面，包含首页、生词本、统计、设置；导出打印从生词本进入。
- 正式选定的本地词库及清晰来源标识。
- 自动保存成功查询、词形归并和重复查询统计。
- 生词本搜索、按日期筛选、按查询次数排序。
- 识别纠错、撤销误收录、个人笔记、手动标记已掌握。
- A4 记忆版、自测版及答案 PDF。
- 最小本地备份与恢复能力，避免积累的记录随卸载丢失。
- 完整的权限拒绝、会话中断、写入失败和导出失败提示。

### 3.3 P2：证据表明确实需要后再做

- 下划线取词、连续多词查询。
- 原句保存、短语查询。
- 发音和更丰富的词条详情。
- 分屏和其他学习 App 的兼容。
- 可选联网补充或语境解释，单独标注来源。

### 3.4 当前明确不做

账号系统、云同步、社交排行榜、自动刷题、答案分析、整页翻译、自动生成背诵课程、多词典插件市场、任意 MDX 导入、iPad 版本、应用商店上架。

不绕过海文的安全机制，不修改海文软件，不自动点击答案，不抓取课程或题库。

## 4. 使用流程与交互设计

### 4.1 App 主界面与开始学习

#### 主界面分工

建议保留四个清楚的入口；具体布局开发时再确定，不在本方案中固定视觉样式。

| 页面 | 主要内容 |
|---|---|
| 首页 | 显眼的“悬浮查词”开关、真实运行状态、今日查询与新增生词摘要、生词本快捷入口 |
| 生词本 | 搜索、筛选、释义与笔记、掌握状态，以及导出打印入口 |
| 统计 | 按日期查看查询次数、新增生词和重复查询情况 |
| 设置 | 词库来源与版本、权限说明、备份恢复与相关设置 |

主界面不是只用于申请权限的启动页。用户可以完全不开悬浮窗，只打开 App 整理生词、查看统计或导出打印；这些操作不应要求屏幕捕获授权。

#### 开关与会话规则（推荐默认）

- 首次打开 App 默认关闭悬浮查词；普通打开主界面不自动开启捕获。
- 用户打开“悬浮查词”开关后，才按需请求权限并初始化；过程中显示“正在准备”，就绪后才显示“已开启”。
- 开启失败、用户取消授权或系统结束会话时，开关恢复关闭，显示原因；不显示一个虚假的开启状态。
- 开启后切换到海文或暂时离开本 App 主界面，不等于关闭悬浮查词；在系统允许且会话有效时继续提供入口。
- 用户主动关闭开关时，移除悬浮按钮和临时取词界面，停止捕获及相关前台服务，释放资源；不是仅把按钮藏起来。
- 通知里的“停止查词”执行同一关闭流程，主界面状态同步更新。
- 关闭悬浮查词不删除生词，不退出或禁用主界面；此前已确认的保存任务仍须完成或报告失败。
- 重新开启时按需要重新授权；应用进程结束后再次启动，先读取真实状态，不凭上次开关值自动重启捕获。
- “收起悬浮按钮”只表示缩小或贴边，仍处于开启状态，不能混同于“关闭悬浮查词”。

以上是拟定行为，尚未实现。开关控制的是本次悬浮查词运行状态，不会自动撤销用户在系统设置中授予的悬浮窗权限。

#### 开始学习步骤

1. 打开 App 首页，将“悬浮查词”开关打开。
2. 若尚未授予悬浮窗权限，引导用户到系统设置开启。
3. 发起屏幕捕获授权；用户拒绝则不启动，也不循环弹窗。
4. 初始化识别模型、打开词库、完成一次受控预热。
5. 显示“查词已就绪”，再进入海文考研。
6. 学习中保留小型悬浮按钮及可停止服务的通知入口。

启动准备时间单独测量，不混入每次查词速度，也不能以“正在预热”掩盖漫长的启动等待。

Android 官方要求在新的 MediaProjection 会话前征得同意；不能复用失效令牌来避免授权。[S1]

### 4.2 查一个词

1. 点击悬浮按钮。
2. 临时隐藏本工具的可见浮层，获取一帧有效的新画面。
3. 将该画面作为只读临时背景，覆盖一层明确标记的取词界面。
4. 用户框住单词，选区边框可见。
5. 松手后识别选区及必要边缘，显示识别文字和基本释义。
6. 保存成功查询；可撤销误收录。
7. 点击“返回做题”或系统返回，移除临时界面。

**“临时静态画面”不等于暂停海文软件。** 本工具不承诺暂停视频、答题计时、自动翻页或底层网络活动。取词界面应显示“取词中”，避免用户把静态副本误认为仍可答题的原页面。

### 4.3 框选与下划线的取舍

首轮用框选：目标边界明确，便于判断错误来自选区还是 OCR。

下划线是后续体验优化：需要识别划线附近的文字行、将路径映射到单词边界，并处理划到两个词、跨行和上下两行距离接近等情况。不能仅识别笔画那一条窄带。

当框选稳定后再比较：下划线是否减少操作时间，是否增加选错词。如果优势不明显，保留框选作为默认方式。

### 4.4 释义卡片

基本卡片按以下顺序显示：

- 识别出的原始词形。
- 对应词头；存在歧义时明确列出候选，不隐式替换。
- 词性、简短中文义项。
- 词典名称 / 版本入口。
- 保存状态、纠正、撤销、关闭。

默认展示必要内容，其余按需展开。折叠长释义应使用明确的“更多”，不能无提示截断导致意思不完整。

音标只有词库确实提供且字体显示正常时才展示，不临时生成冒充词典数据。卡片不默认包含例句和发音，避免增加首屏等待和授权范围。

### 4.5 连续操作与误触

- 悬浮查词已开启但未选词时，只让悬浮按钮本身接收触摸，不放置全屏透明拦截层。
- 取词时临时层接收操作，不能让划选动作传给底下的答案按钮。
- 返回操作只退出当前层，不能触发海文的返回或提交答案。
- 识别中重复操作取消旧请求或忽略重复提交；旧结果不能覆盖新选区。
- 屏幕旋转或捕获尺寸变化时使旧画面失效，提示重新选词。

## 5. 词典来源与准确性方案

### 5.1 先区分三个问题

1. **选的是不是用户想查的词？** 属于交互与 OCR。
2. **词头和中文释义是否正确？** 属于词形处理与词典内容。
3. **在这句话里具体是哪一个意思？** 属于语境判断。

第一版重点保证前两项，展示常用义项，不承诺自动选出句中唯一正确释义。

### 5.2 候选方案比较

| 方案 | 响应路径 | 内容与许可判断 | 本方案态度 |
|---|---|---|---|
| 经授权的离线英汉学习词典 | 本地 | 必须确认具体内容、离线与导出权利 | 正式版优先调查 |
| 牛津官方数据产品 | 取决于实际交付方式 | 产品存在不等于已获得英汉离线包或打印许可 | 候选，不预先拍板 |
| 牛津在线 API | 依赖网络与接口 | 需确认语种、字段、缓存和保存条款 | 不作唯一核心路径 |
| ECDICT | 可转换为本地词库 | 仓库列出 MIT，但内容来源和质量仍须审查 | 原型候选，不能冒称牛津 |
| 来源不明的“牛津词库包” | 可能本地 | 版本、来源、许可与完整性均不明 | 不采用 |
| AI 即时生成释义 | 依赖模型与部署方式 | 不作为词典原文或确定答案 | 不进入第一版主路径 |

牛津官方提供词典数据与 API 产品；本次没有获得适用于本项目的离线英汉报价、具体版本和授权承诺。[S5][S6]

**对前期讨论的收敛：** 不把“牛津品牌”“某版牛津高阶英汉双解”“Oxford API 的可用语言对”视为同一件事。具体英汉覆盖、字段和许可均须在选型时核验。

ECDICT 的项目说明列出了中文释义、音标、词形等字段，也描述了多来源汇集过程；这些信息支持技术可用性调查，不等于本项目已经核验了每条内容。[S4]

### 5.3 正式采用前的清单

每个候选词库至少核对：

- 内容提供方、正式名称、版次 / 版本、获得日期。
- 英汉释义、词性、词形、音标的实际完整程度。
- 是否支持离线嵌入个人应用，是否有设备数、期限限制。
- 是否允许保存所查词条、生成个人生词本、导出和打印。
- 署名、版权声明、更新和停止使用要求。
- 若以后分发 APK，是否需要另行授权。

本方案不是授权结论。没有确认的权限不得以“个人使用”“已购买会员”代替。

### 5.4 内容验证不能只看词条总数

建议用用户真实阅读中遇到的词构成独立检查集，包含常见词、多义词、词性转换、不规则词形、长词以及标点相邻词。

检查时分别记录：

- 是否收录正确词头。
- 是否有适合学习的中文解释，是否存在明显错义或词性错配。
- 是否遗漏影响这批题目阅读的常见义项。
- 变形词是否错误归并。
- 来源和版本是否能追溯。

人工核验宜依据合法取得的可靠参考资料，必要时请英语老师协助。不能由另一个 AI 随口确认后就标为“权威核验”。

首轮抽样只能证明该样本上的表现，不代表整部词典或全部考研词汇都达到同样准确率。

### 5.5 词形处理规则

推荐顺序：

1. 保留识别原文，同时清理明显外侧标点。
2. 优先精确查当前形式，不先粗暴去掉 `s`、`ed`、`ing`。
3. 若词库提供词形映射，查询对应词头。
4. 多种映射都成立时显示候选，不能自动假装唯一正确。
5. 仍无结果时显示“未收录 / 请检查识别”，允许用户编辑。

例如 `saw`、`left` 不能仅凭词尾规则认定为某个动词变形。候选纠错也不能因为一个错误字符串碰巧命中词典，就认为 OCR 已正确。

保留大小写和撇号等有意义的信息，原始显示与检索用的标准化字符串分开存储。

### 5.6 低可信度处理

- 选区跨多词、文字太小、候选接近或匹配异常时，要求重新选取或确认。
- 不假设 OCR 库在所有场景都提供可比较的置信分数，不虚构“99% 确信”。
- 用边界、字符结构、词库匹配和歧义情况辅助判断，但词库命中不是正确性证明。
- 未确认的歧义记录不进入默认打印清单。

## 6. 技术架构与关键实现

### 6.1 推荐技术选择（设计建议，未安装依赖）

| 层次 | 推荐 | 选择理由 |
|---|---|---|
| 平台 | 安卓原生、Kotlin | 直接处理窗口、捕获和生命周期 |
| 主界面 | 简单的原生界面；具体 UI 方案开发时确定 | 不让界面框架选型拖延核心验证 |
| 悬浮入口 | WindowManager 应用悬浮窗口 | 对应跨应用入口；需要相应权限 [S7] |
| 画面获取 | MediaProjection + ImageReader + 合规前台服务 | 官方捕获路径 [S1] |
| OCR | 优先试验打包的 ML Kit 拉丁文字识别模型 | 模型随应用交付，不依赖首次动态下载 [S2] |
| 词典存储 | 带索引的本地 SQLite 只读数据库 | 独立于个人记录，按词头检索 |
| 学习记录 | Room / SQLite | 本地持久化，明确迁移与事务边界 [S8] |
| 导出 | 本地 PDF 生成，接入系统文件保存 | 按固定纸张布局；系统有 PDF / 打印相关接口 [S9] |

具体依赖版本、最低 Android 版本和目标版本在开发时按设备和官方要求确定，不在方案里使用未经验证的版本号。

不先做后端、不引入微服务、不建立通用词典插件框架。

### 6.2 模块边界

```text
悬浮入口 / 学习会话
        ↓
捕获协调器 → 一帧有效画面
        ↓
选词界面 → 区域与坐标映射
        ↓
本地 OCR → 原始词形 / 候选
        ↓
本地词典查询 → 词头 / 释义 / 来源
        ↓
释义卡片 ──→ 查询事件与生词本
                         ↓
                   筛选 / 统计 / PDF
```

职责分开以便定位问题，但不为未来多平台做大规模抽象。

### 6.3 捕获会话与新鲜画面

- 每次学习启动建立一个有效会话，不为每个单词重新创建虚拟显示。
- 用户点击查词时，先移除本工具的遮挡，再等待可确认的新帧。
- 不靠固定等待若干毫秒就假定画面更新；结合帧事件、时间和窗口状态核对。
- 不把上一次题目的缓存画面当成当前题目。
- 获得目标帧后，在独立副本上选词；不能反复捕获自己的取词界面形成套叠。
- ImageReader 缓冲及时释放；只保留所需的短期画面，不积累整个会话视频。
- 不持续对全屏逐帧 OCR；会话保留期间仍可能有系统捕获开销，功耗需要实测。

Android 的会话停止、尺寸变化与资源回收需按官方回调处理。[S1]

### 6.4 捕获范围

优先试验只分享海文应用窗口，以缩小可见信息范围；但它的捕获尺寸和系统栏范围可能不同于全屏，需要单独映射。[S1]

技术原型可比较单应用捕获与全屏捕获。若最终需要全屏方案，应明确告知用户：会话有能力看到全屏内容，不是从系统层面只获得框选的那个词。

第一阶段不同时承诺支持两种模式，也不要求用户关闭安全保护。选择结果以实测和隐私说明为准。

### 6.5 坐标转换

取词界面坐标与捕获图像像素不一定相同。需要明确处理：

- 原始图像尺寸、显示缩放比例。
- 系统栏、窗口边距与居中黑边偏移。
- 横竖屏、屏幕密度。
- 应用窗口捕获与整屏捕获的差异。
- ROI（实际识别区域）的扩边与图像边界裁剪。

每次布局或尺寸变化后重新计算，不能沿用旧参数。横屏、竖屏分别用已知位置的文字核对选中范围。

### 6.6 OCR 策略

- 先识别框选区域，并留出不截断字符的边缘。
- 保持文字可读清晰度，不为了速度任意缩小到不可识别。
- 若选区过窄或无结果，最多进行一次有明确原因的局部扩边重试。
- 重试耗时必须计入查词指标，不能从统计里删除。
- 不以反复识别整屏来掩盖取词规则问题。

ML Kit 提供打包与动态下载两种方式；本方案选择打包候选，但断网初装、该平板环境和具体输入质量仍需实测。[S2]

### 6.7 并发与生命周期

- OCR、词典读取、持久化和 PDF 生成不阻塞界面线程。
- 每次查询拥有独立标识，结果只归属于对应选区。
- 用户取消后，不再展示或自动收录迟到结果。
- 服务停止时释放捕获、图像和识别资源。
- 不让旋转、重复点击或回调重复增加查询次数。

## 7. 响应速度预算与优化顺序

### 7.1 验收目标，不是性能承诺

| 指标 | 初步目标 | 计时说明 |
|---|---|---|
| 点击悬浮按钮到可选词 | P95 ≤ 500 ms | 点击到新鲜静态画面可交互 |
| 松手到基本释义可见 | P50 ≤ 400 ms；P95 ≤ 800 ms | 包含排队、必要重试、查询和渲染 |
| 单次软件等待总时长 | P95 ≤ 1,300 ms | 同次操作前后等待相加，排除用户划选用时 |
| 偶发慢查询 | 超过 1,500 ms 必须记录原因 | 不能以平均值掩盖卡顿 |
| 启动就绪 | 单独报告首次 / 冷启动 / 热启动 | 用户操作授权耗时与软件准备耗时分开 |

P95 的含义是：约 95% 的样本不超过该时间。两个阶段的 P95 相加不等于总体 P95，必须逐次记录完整链路后再计算。

如果这些目标在真实平板上无法达到，应给出实测分布、瓶颈和选择，不把目标改写成“已通过”。

### 7.2 松手后的内部设计预算

| 阶段 | 初步预算 |
|---|---:|
| 选区确认、裁剪与输入准备 | 100 ms |
| 本地 OCR | 450 ms |
| 词形处理与词库检索 | 100 ms |
| 卡片渲染 | 100 ms |
| 余量 | 50 ms |
| 合计 | 800 ms |

上述只用于帮助定位工程瓶颈，不是各组件的已有测量结果，也不能靠相加各阶段分位数宣称总链路达标。

### 7.3 优化顺序

1. 先查是否存在重复初始化、重复画面转换、主线程工作。
2. 再优化选区大小、位图复制、词典索引和必要缓存。
3. 缓存以词库版本和查询键为边界，更新词库后不能继续显示旧结果。
4. 不默认批量预识别整页；只有实测证明能改善体验且功耗可接受才考虑。
5. 不把在线接口或大模型加入基本释义显示前的路径。

### 7.4 必须测量的体验指标

- 首次查询、重复词、新词分别计时。
- 无匹配、歧义、识别错误也计入尝试总数。
- 保存耗时单独测量，首屏快速不能以丢数据为代价。
- 计时使用单调时钟，日历时间仅用于学习记录。
- 开启网课、切换 App、学习 30 分钟后的表现单独报告。

## 8. 本地数据与统计规则

### 8.1 两类数据分开

- **词典库：** 只读内容，带版本、来源和使用约束。
- **个人学习库：** 查询事件、生词、个人笔记和掌握状态。

更换词库不能删除个人记录。词典内容是否允许在个人库里复制保存，需要先确认许可；未允许保存的来源不得悄悄永久缓存。

### 8.2 最小数据结构（逻辑设计，不是已建表）

| 对象 | 主要字段 | 说明 |
|---|---|---|
| 词典来源 | 来源 ID、名称、版本、许可记录、内容摘要校验值 | 标识具体数据版本 |
| 词条 | 词条 ID、词头、词性、义项、可用音标 | 内容来自所选词库 |
| 词形映射 | 原词形、候选词条 ID、词形类型 | 允许一对多 |
| 查询事件 | 事件 ID、时间、原始 OCR、最终词形、词条关联、状态、是否撤销 | 作为查询次数事实来源 |
| 生词项 | ID、明确词头键、关联来源、个人笔记、掌握状态 | 同词在确认后归并 |
| 释义快照 | 生词项关联、来源版本、允许保存的释义、保存时间 | 仅在许可允许时持久化 |

为了控制复杂度，原型不实现完整数据库；日用版根据实际词库结构落地。不预先建立跨所有词典的自动同义词归并系统。

### 8.3 何时计一次查询

一次主动选词成功显示基本释义后，生成一个成功查询事件。

- 同一次操作内部重试、回调重复、界面重绘不重复计数。
- 未找到词、取消、明确识别错误不计入已学词次数。
- 同一个词在另一次主动选词中再次成功查询，可增加一次。
- 多候选未确认时保留为待确认状态，不归入正式生词。
- 手动更正后，以最终确认词条为准，原错误记录标记纠正 / 撤销，不双计。

一次成功事件与对应生词更新应在同一事务中完成，并以事件 ID 防重复。查询次数可从有效事件聚合，不维护两套互相冲突的事实来源。

### 8.4 自动保存与状态提示

基本释义先显示，保存异步进行；卡片先显示“保存中”，写入确认后才显示“已收录”。

保存失败时保留清晰提示和重试入口。应用被关闭前尚未写入的数据存在丢失风险，不能在未提交时告诉用户已经保存。

同一个词再次查询默认不覆盖个人笔记。撤销当前收录应撤销该事件；如果之前已有同词记录，不能连同历史查询一起删除。

### 8.5 生词本统计

第一版提供：

- 今日成功查询次数。
- 今日新增生词数（去重）。
- 选定日期范围内查询次数最多的词。
- 待复习 / 已掌握数量。
- 首次查询和最近查询时间。

查询次数只表示用户查了多少次，不能自动解释成考试频率或记忆掌握度。掌握状态由用户手动标记。

按设备本地时区划分学习日；记录时间保存统一时间戳，避免跨日汇总时混淆。

## 9. 导出、打印与数据备份

### 9.1 导出入口

用户在生词本选择范围：今天、日期区间、未掌握或手动勾选；再选择排序方式和模板。

导出开始时冻结所选记录快照，避免打印过程中新增词条导致页数和内容不一致。文件写入成功前不提示导出完成。

### 9.2 两种 A4 模板

**记忆版：** 序号、英文词头、需要保留的原词形、词性、中文释义、可选个人笔记。

**自测版：** 序号、英文词头、足够书写的留白；答案页使用相同序号。

统一要求：

- 黑白打印清晰，不依赖彩色区分。
- 日期范围、页码、排序方式明确。
- 长释义自动换行；尽量不把一个词条拆到两页。
- 中文和音标使用许可允许的字体，检查缺字与 PDF 字体嵌入。
- 打印正文使用经过确认的释义或个人笔记，来源可追溯。
- 未确认识别结果默认不导出。
- 不默认附带题目整页截图、课程内容或整句题干。

具体字号、列宽和每页条数根据真实 PDF 渲染结果调整，不在纸面方案中承诺固定能容纳多少词。

### 9.3 打印边界

第一版以导出可打印 PDF 为交付重点，可交给现有打印流程使用。安卓提供自定义文档打印与 PDF 相关接口，但本项目尚未测试任何实体打印机。[S9]

PDF 可打开、页面渲染正常和实体打印通过是不同验证层级。不得把前者写成后者。

### 9.4 最小备份与恢复

打印文件不是完整数据库备份。

日用版建议支持用户主动导出学习记录备份，包含格式版本、查询事件、个人笔记和状态。词典原始库不默认随备份导出，释义快照按许可决定。

恢复前校验结构、大小、版本和引用关系；第一版仅允许导入到空学习库，已有记录时明确拒绝直接覆盖，避免实现复杂合并或造成数据损失。

词库缺失时仍显示可恢复的用户记录，并提示安装相应词库，不伪造来源。

## 10. 隐私、权限与异常处理

### 10.1 权限最小化

拟使用悬浮窗、屏幕捕获及对应前台服务所需能力；文件导出使用用户主动选择的保存位置。

不请求摄像头、麦克风、联系人、位置；第一版不依赖无障碍服务去读取其他应用内容，不请求全部文件访问。

核心离线版原则上不声明网络权限，不接入广告或第三方行为分析 SDK。若后续确需联网功能，应重新说明发送哪些数据并由用户主动触发。

### 10.2 画面处理

- 不录音，不保存整场学习视频。
- 临时画面只用于当前取词，结束后释放引用与缓冲，不自动写入相册。
- 不把截图、题目内容或查询正文写入普通性能日志。
- 性能日志只保留耗时、错误类型和匿名操作 ID，并限制容量。
- 不承诺托管内存释放等于底层像素被立即安全擦除；以不落盘、不上传、缩短持有时间为默认策略。
- 个人记录的系统自动备份策略须显式配置；若承诺只保存在本地，不应无意开启系统云备份。

### 10.3 异常处理表

| 场景 | 预期行为 |
|---|---|
| 用户拒绝授权 | 保持关闭，说明原因，不连续弹窗 |
| 海文隐藏悬浮窗 | 告知兼容性限制，停止该路径验证，不绕过 |
| 捕获黑屏或受保护页面 | 明确提示无法获取，不继续猜词 |
| 会话因锁屏或系统停止失效 | 清除旧画面，状态变为已停止，再次使用时重新授权 |
| 画面未更新 | 不展示上一页作为当前页，提示重试 |
| OCR 无文字 | 提示扩大或重新选区，不空白卡住 |
| 选中了多个词 | 提供候选或要求重选，不任意取第一个 |
| 词库未收录 | 提示未收录，不自动调用 AI 编造释义 |
| 写入失败或空间不足 | 显示未保存，允许重试；不显示已收录 |
| PDF 导出取消 / 失败 | 保留生词数据，不声称成功 |
| 旋转 / 窗口变化 | 当前选区失效，重建坐标后继续 |

Android 提供禁止捕获和隐藏覆盖窗口的安全机制，截图成功只能说明用户测试过的页面与操作，不能推及所有海文页面和未来版本。[S3]

## 11. 验证计划与验收门槛

### 11.1 测试分层

| 层级 | 能证明什么 | 不能证明什么 |
|---|---|---|
| 本地单元 / 静态检查 | 词形规则、事件计数、数据库和导出逻辑 | OPPO 兼容和真实延迟 |
| 模拟器 / 仪器测试 | 基础界面、生命周期与部分系统交互 | 海文实际窗口策略和设备功耗 |
| OPPO Pad 3 + 海文实测 | 目标环境实际流程和速度 | 所有安卓设备普遍兼容 |
| 实体打印 | 选定打印流程中的纸面效果 | 所有打印机兼容 |

当前上述软件测试均未执行；目前只有用户确认过题目手动截图可用。

### 11.2 建立真实样本

建议准备 200 次独立选词尝试，来自若干真实题目页面，覆盖：

- 普通字号、偏小字号、长词和标点相邻词。
- 规则与不规则词形、多义词。
- 实际需要的横屏和竖屏。
- 新词和重复查询。
- 白底与用户实际使用的其他显示模式。

开发调参使用的样本与最终验收样本分开。记录样本选取规则，不用只挑清晰大字的样本来报高准确率。

### 11.3 初步准确性门槛（需用户认可）

| 指标 | 定义 | 初步目标 |
|---|---|---|
| 首次取词正确率 | 第一次自动结果英文与人工标注一致 / 全部合规选词尝试 | ≥98% |
| 首次端到端成功率 | 首次正确取词且命中正确词条并展示释义 / 全部尝试 | ≥95% |
| 词库覆盖率 | 有合适词条的不同测试词 / 全部不同测试词 | ≥98% |
| 明显释义错误 | 人工审阅样本中的明显错义、错词性或错归并 | 正式验收样本零未解决问题 |
| 静默错误收录 | 选错、识别错或错误归并，仍正常记为已确认 | 单独计数；发现后必须修复或明确阻断 |

98% 仍意味着平均约每 50 次可能出现一次错误，不是绝对准确。若用户不能接受这一体验，需要提高门槛并评估可实现性，而不是隐藏剩余错误。

“样本零未解决问题”是该样本的门槛，不代表整体词库绝对无误；先修复，再用新的独立样本复验。

### 11.4 速度与可用性验证

- 至少记录一轮完整真实查询集的各阶段耗时。
- 报告 P50、P95、最大值、失败率、重试次数；失败和超时不能剔除后只报成功平均值。
- 单独展示冷启动首查和就绪后的查询，不把前者藏起来。
- 初次安装后断网启动验证，确保没有隐含模型下载依赖。
- 与用户原先截图翻译方式做同类任务对比，记录完成查询的总操作时间和额外点击数。
- 日用版使用接近发布配置的安装包计时，不仅以调试环境数据下结论。

### 11.5 稳定性、功耗与误触

- 连续使用 30 分钟，完成至少 100 次查询，检查崩溃、浮层残留和内存增长。
- 对比相近亮度和负载下，工具关闭与会话开启的耗电、温升及流畅度；这是初步趋势观察，不宣称精确续航测量。
- 反复取消、返回、旋转、锁屏和系统停止捕获。
- 未开启悬浮窗、拒绝捕获授权时，仍能使用已有生词、统计与导出功能。
- 主界面开关与通知停止操作状态一致；关闭后无浮层、无继续捕获，已保存数据不受影响。
- 验证切换到海文不会被误判为主动关闭；进程结束后重开 App 不会静默恢复捕获。
- 明确检查海文答案是否被误点、是否返回到错误页面。
- 使用实际海文视频 / 做题流程检查捕获是否与其他功能冲突。

### 11.6 数据与 PDF

- 同词不同词形查询、重复回调、撤销和纠错，验证计数。
- 关闭重启后保留数据，存储异常时不虚报成功。
- 用 1、50、200 条记录，以及长中文、音标、长英文等内容检查分页。
- PDF 每页渲染检查，不裁字、不缺字、序号与答案对应。
- 备份恢复到空库后，比较有效事件、生词和笔记。
- 实体打印至少一页由实际打印确认，未执行则标记待验证。

## 12. 开发阶段、交付物与停止条件

### 阶段 A：确认环境与兼容性

步骤 → 检查系统和海文版本；验证授权、悬浮窗、画面获取和坐标。  
验证 → 在平板实际题目页展示新鲜、无遮挡画面，并可安全退出。

交付：兼容性检查表、运行条件、已知限制。

停止条件：目标页面无法捕获、浮层不可用，或必须绕过保护才能工作。此时先讨论替代流程，不继续投入完整生词本。

### 阶段 B：最小快速查词原型

步骤 → 提供带悬浮查词开关的基本首页，接入本地 OCR 与测试词库，完成框选、释义卡片和耗时记录。  
验证 → 用真实题目执行速度、选词准确性和误触检查。

交付：可安装测试包（仅用户批准后安装）、测试报告、演示数据声明。

停止条件：实测不比现有截图流程省事，或识别错误需要频繁手动修正。先解决瓶颈，不能以增加其他功能代替。

### 阶段 C：正式词库决策

步骤 → 核验候选词库的内容、许可、费用和离线能力。  
验证 → 真实词条抽样、词形检查，以及保存与打印权限确认。

交付：词库选型结论、来源与版本记录、费用和限制。

这一阶段可以在环境验证后与原型探索并行推进，但未通过前，原型不能标为正式学习版。并行是工作安排建议，不代表当前已创建其他代理任务。

### 阶段 D：个人日用版

步骤 → 完善首页、生词本、统计与设置界面，接入生词事件、本地保存、搜索统计、纠错、PDF 和最小备份恢复。  
验证 → 数据一致性、断网、异常恢复、连续学习和打印版面检查。

交付：日用候选安装包、使用说明、测试证据、备份与回退方法。

### 阶段 E：交互优化

步骤 → 根据真实使用反馈决定是否加入下划线取词和连续查词。  
验证 → 与框选基线对比速度、错误率、功耗，不接受无证据的“更智能”。

### 工期说明

粗略工作量：兼容性与原型通常按数天至一两周量级预留；生词本、导出和日用稳定性再按数周量级安排。前提是熟悉安卓开发、设备可测试且词库来源可解决。

这不是报价或交付日期。词典商业授权等待、设备适配问题和从零学习开发的时间不在上述估算中。完成阶段 A 后再制定可执行排期。

### 13.1 成本结构

### 13.2 风险排序

| 风险 | 影响 | 应对 |
|---|---|---|
| 捕获或悬浮不兼容 | 核心流程不可用 | 优先阶段 A；不绕过保护 |
| 词库许可或质量不满足 | 不能放心长期学习和打印 | 内容选型独立过关，不拖到最后 |
| 小字和复杂排版识别差 | 反复重选，失去效率 | 用真实页面验证，保留扩边和纠错 |
| 字符识别正确但词形归并错 | 学错词或统计失真 | 精确查询优先，歧义不强行合并 |
| 系统结束捕获会话 | 需要重新授权 | 明确状态与恢复入口，不静默假装运行 |
| 长时间捕获耗电 | 影响学习续航 | 不逐帧 OCR，实测功耗，提供显著停止入口 |
| 自动收录错误词 | 污染打印材料 | 保留原词形、撤销与待确认状态 |
| 数据损坏 / 卸载 | 生词丢失 | 最小备份恢复，迁移验证，不自动清空 |

### 13.3 必要时的替代路线

- 悬浮不兼容但截图分享可用：改为“截图分享给本工具”，保留本地识别和生词本。应明确承认操作变多，不称为与原目标等价。
- 授权离线词库无法获得：继续仅做技术验证，或由用户选择其他可靠来源；不偷偷改成在线 AI 释义。
- 下划线容易选错：保留框选，不为了模仿扫描笔牺牲准确度。
- 未收录词需要补充：显示缺词并允许个人笔记；联网补查须作为用户主动选择的独立功能。
