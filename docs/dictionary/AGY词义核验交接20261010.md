数据根目录：`.tools/dictionaries/exam-meaning-review-20261010/agy-handoff/`，属于忽略的本地运行产物，不提交词库、结果或日志：

- `inventory.json`：来源清单哈希、原结果逐文件哈希、新批次哈希、总数与排除口径。
- `batches/*.json`：只读固定任务，保留 `pending_senses / covered_senses / source_variants / previous_review / prior_incremental_review`。
- `instructions.md`：AGY 逐词真实查证规则。
- `results/<handoff_batch_id>.jsonl`、对应 `-summary.md`：AGY 仅可写其当前批次的这两个输出。
- `run-state.json`：真实运行/阻碍状态、原会话与当前批次；不能把已退出进程标为 running。
- `pilot-accepted.json`：试跑查证抽检后才创建，绑定输入/结果哈希。当前不存在。
- `progress.json`：主线程结构门禁统计；不是专业语义认证。
- `logs/`：真实 CLI 输出/错误，可能含账号关联 URL，仅本地保存，不复制到说明或提交。
- `dispatch.lock`：阻止两个本地调度器同时写状态或派发。

AGY 的 `handoff_batch_id` 是新小批 ID，`batch_id` 必须仍为该词原 `source_batch_id`；`original_senses` 原样复制 `pending_senses`。旧结果不能覆写，也不能偷偷写进 App。

## 主线程续作步骤 → 验证

1. 查看真实 `run-state.json` 与私有错误，确认网络原因已实际解除、没有 AGY 正在执行；不要仅因心跳触发重试。
2. 校验交接 → 运行 `review_agy_meanings.py ... summarize`，核对原清单、全部批次与旧结果哈希、唯一词头和原义。
3. 显式恢复同一会话的 5 词试跑 → `run --resume-blocked --max-batches 1`。该开关仅限阻碍已经解除时使用。
4. 逐行门禁并真实核对试跑字典证据 → `approve-pilot --evidence-checked`；没有字典证据、缺行或仅空 SUCCESS 均不能批准。不因结构通过而批准候选修订。
5. 试跑通过后分批串行续发 → `run --max-batches N`。同一会话、每批校验后再下一批，保留已有行，不重审相同义项；遇额度、429、权限、账号或输出错误立即保存并停下，不循环重试或换 GPT。
6. 已有行但 unresolved 或候选仍不算完成；完成首轮只是“均有真实尝试”，还需要补核与候选独立复核。新义项有可靠支持或候选正式验收，才可剔除。此工具不自动改库或 App。
