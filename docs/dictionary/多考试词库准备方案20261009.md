# 多考试离线词库：分享方案评估与准备

日期：2026-10-09。状态：**来源/数量检查、五个 Luna High 独立统计与本地 SQLite 合库已完成；释义准确性验收、适用内容许可与 App 接入未完成。**

## 结论

“保留现有词书释义，先机器检查，再对缺项/冲突做有依据的 AI 审校”值得采用。**不采用“凑满18,000词、默认全部正确、AI凭记忆补全、马上作为正式词库打包”**。词书来源、考试分类证据、释义核验、再分发依据必须分别记录。

用户提供的分享讨论为：<https://chatgpt.com/share/6ac8eb65-bf70-83e8-bcb5-a4a344862243>。本次读取完整分享内容，重点评价讨论最后形成的 kajweb/有道优先、ECDICT辅助、AI只查异常的路线；分享中的估时、费用和“模型完全胜任”不是本项目已验证事实。

## 内容与来源证据

1. kajweb README 自述数据抓取自“X道背单词(app)”；Qwerty README 明确列 kajweb 为字典来源。这是来源声明，不是两套独立审核证据。
2. 本次固定 kajweb 根目录与 GitHub仓库元数据未发现明确的数据再分发许可，仓库 `license` 字段为 null；Qwerty显示 GPL-3.0 软件许可，但这不能当作商业词典原始内容权利已解决的证据。**尚未确认释义可随 APK 再分发，不把源数据或整段释义提交到本项目。**
3. 本轮十个文件的释义字段没有空白记录，但专四/专八各有一条未检出汉字的 `fiance`。有非空字段不等于语义正确。
4. 英美音标均空的记录：kajweb各书分别59/41/8/37/148；Qwerty各书分别0/0/0/34/137（顺序为四级/六级/考研/专四/专八）。这是记录数，不是去重词数，更不是读音正确率。
5. 合并后6,084个词头具有不止一种翻译字符串。这是审校候选规模，**不是6,084个错误**；词性、词书取义、标点或表达变化都可能造成差异。
6. ECDICT按同一词头规范化进行精确匹配：12,784个存在且有中文字段，1个未匹配（`barometre`）。不自动改为其他拼法；这不是词形覆盖率或释义准确率。
7. 词书ID仅证明“该备考词书收录”。在没有指定版本的权威考试词表逐词证据前，界面不显示“官方考纲全覆盖”。

## 调整后的实施顺序 → 验收证据

### 1. 固定词表和许可边界（本轮已做部分）

- 以kajweb上述五书作为候选分类主索引，Qwerty只作同源整理/格式比较，不计作第二个独立权威。
- 保留每个来源的bookID、版本、文件SHA256、词书类别；同一词保留多个标签，不以覆盖写丢分类。
- 本轮已实算数量、缺项、重叠和ECDICT精确匹配；**未形成获准打包的正式释义资产，也未验官方考纲**。
- 确认适用的数据内容许可，或换用授权清楚的释义来源；“AI改写”不是绕过来源问题的方案。

### 2. 小批内容审校试点（待做）

- 建议先用100–200个词，不直接启动全库AI重写。覆盖常见多义词、词形歧义、已有已知问题、音标缺失、同源不同字符串和目标海文题目中的真实词。
- 开发样本和独立复验样本分开；样本经过修订后不再叫独立验收集。
- 用户指定 Luna High；本轮五个统计代理均使用 `gpt-6-luna`、`reasoning_effort=high`。后续若开展内容审校，沿用此设置，并按外部依据与独立复验决定是否通过，**不是按模型自报置信度通过**。
- 每条候选输出：词头、词性/义项、原值、拟修改值、依据来源及准确位置、理由、核验状态。拿不到依据时标记待核验，保留原值。
- 官方Oxford仅作已获准方式下的对照；不批量复制英文释义/例句，不承诺免费取得整套授权参考数据。
- 有道原值作为候选保留；ECDICT只做有依据的补缺。音标还必须对齐义项/词性及英美规范，不能仅凭同拼写盲补（例如lied的歌曲名词和lie动词读音不同）。
- 验收：试点中的阻断性错误零未解决；报告实际检查范围及剩余疑点，不外推全库准确率。

### 3. 批处理与内容候选构建（待试点通过）

- 常规格式/重复/缺字段工作交给脚本；AI只检查需要语义判断的条目，逐批落盘、可中断恢复、保留原文，不反复发送整个词库。
- 保留数据状态：待核验、证据核对完成、需复核；“同源两份一致”和“AI说正确”不得直接升为完成。
- 生成词条内容、分类标签和学习数据的分离候选。未解决的语义/许可项不进入正式学习包。
- 通过零悬空映射、唯一键、同形候选保留、固定哈希与可重复构建等结构门禁；这些仍不替代内容验收。

### 4. App接入及本地测试（待内容/许可门槛满足）

- 沿用现有独立Android工程，不增加网站或新背诵模块；保留离线OCR、不新增联网查词权限。
- 查词输入、悬浮卡片、旧生词记录和PDF分别核验来源/版本，保留笔记、掌握状态及历史计数，不清库。
- 数据加载和查询不阻塞主界面；加载失败不回退假释义；同形异义须保留候选；异步迟到/取消不能误保存。
- 功能小版本候选为0.2.0/code3，**前一阶段已有未完成草稿，不等于已有可交付0.2.0安装包**。
- 验证parser/JVM单测、构建、lint及设备测试包编译；OPPO安装和实机海文场景另行获授权再测试。

## 五代理独立统计与本地合库（已完成）

按用户要求，五个代理均显式设置为 `gpt-6-luna`、`reasoning_effort=high`，各负责一个考试分类。每个代理直接读取固定原文件、使用独立统计逻辑，不调用主线程的审计/合并程序。这里的“独立”指统计实现独立，不代表两套上游词书互为独立权威，也不代表进行了释义审校。

| 分类 | 代理 | 两源词头交集 | 两源去重并集 |
|---|---|---:|---:|
| 考研 ky | Cicero | 3,310 | **4,950** |
| 四级 cet4 | Hooke | 2,130 | **4,216** |
| 六级 cet6 | Peirce | 948 | **3,475** |
| 专四 tem4 | Goodall | 4,025 | **4,025** |
| 专八 tem8 | Kant | 12,197 | **12,197** |

这些分类相互重叠，不能相加当作总词数。最终跨两源、跨五分类的唯一词头是 **12,785**。合并程序校验每个代理的输入 SHA256、并集数、交集数以及完整排序词头列表；五份报告均 `matched`，不是只比较数字。

SQLite 分开保存：

- `words`：12,785 个规范词头（12,783 个单词输入形状，另有 `a.`、`vs.`）。唯一键负责词头去重，不删后缀、不猜词形。
- `word_exams`：28,863 条词头与考试分类关系；一词可属于多个分类。这些标签仍是“该词书收录”，不是官方大纲认定。
- `sources`：10 个固定来源，包含原词书、文件、上游提交、URL、SHA256 和许可/考纲未确认状态。
- `source_entries`：51,474 条原始记录，保留原词头、顺序、原 rank（如有）、英美音标、原释义与原 POS。Qwerty没有独立POS字段时保留 `null`，不猜填；保留不同来源/同词多义字符串，不静默选一条覆盖其他。
- `metadata`：固定来源清单、归一化规则、五份报告哈希、`local_candidate_not_content_approved` / `unreviewed` 状态。

本地唯一交付数据库：`artifacts/dictionaries/exam-vocabulary-20261009.sqlite3`，11,829,248 字节；SHA256 `8509688fa5f66307e6565432e66e99561d257a55114e74e8ea8f080564874d48`。汇总报告：`artifacts/dictionaries/exam-vocabulary-20261009-report.json`。这些是忽略的候选运行产物，**不进 Git、APK 或正式学习包**，没有改学习数据库。
